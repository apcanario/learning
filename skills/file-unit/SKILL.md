# File a unit

**In a thin main chat (S-BW1, 15 Nov 2026)** the chat does not write the course data by hand: a fresh Opus 5.5 filer agent, staged with `python3 kit/thin.py stage filer --row <row> ...`, writes `out/records.json` (the reading-page intro, status, next unit, version, changelog lines, register lines, flag rows, the `courses-index.md` edits, both changelogs), and `python3 kit/thin.py insert out/records.json` inserts it, restoring every file if anything fails. §4 and §6 below say what those records hold; the checks (`index_check.py`, `private_terms.py`, `build.py`, `verify.py`, the publish read-back) are scripts.

**Proposals (standing rule, Pedro, 15 Nov 2026).** The closing reply lists every proposal the work raised, each with what it does and a ⚠ flag on any disruption elsewhere in the project. Each goes into the Carried proposals section of `docs/BACKLOG.md`, is appended to the next row's prompt by `kit/next_prompt.py` (its step 1c) and is worked in that chat unless Pedro removes it. A brief change or a task only Pedro can do stays *proposed*. The W-PB7 same-chat corrections rule is unchanged.

Turns a written unit into a filed one: vault, course data, Academy, index. The procedure is `method.md` §7. The design rule holds throughout: Academy is rebuilt by `kit/build.py` from `design/theme.css`; nothing is styled by hand.

**The course's entry.** Every course is one entry, `courses/<id>/course.toml`, read by `kit/courses.py` (S-DEC1). For a markdown course (Brand + AI, User Experience, any new one) the entry gives the paths used below: `id` (its fresh-check reports go in `audits/<id>/`), `data` (the course's pack: its `course.toml`, whose `[pack]` table `kit/pack.py` reads (S-DEC2); its `briefs.md` sits beside it and its notes files (case file, `syllabus-flags.md`, a register of invented facts) in `courses/<id>/notes/`), `vault` (the folder the unit is filed in) and `sourcing_part` (its own part of `sourcing-standard.md`; Part 2 for a markdown course without the key). Below, `<id>`, `<data>` and `<vault>` mean those values for the unit's course; no step names one course's folders.

## 1. Check the unit
- It is complete: every brief item covered, the deliverable (a markdown course) or Self-test and Carry forward (history) built in full, a Sources list or bibliography file present.
- Its figures (if any) were checked: by the fresh check (a markdown course: section (7) of the fresh-check report) or the fresh checker (history), each figure PASS or fixed.
- It starts with the front matter (code, title, course, model, written, search). Add it if missing; the model is the one that actually wrote the unit.
- If anything is missing, stop and say what; do not file a partial unit.

## 2. Vault
Save to `<vault>/<code>-<slug>.md` for a markdown course, `courses/<course>/<id>-<slug>.md` for a history course (`greece` or `rome`); slug = the title lower-cased, hyphenated, accents and punctuation dropped. If the vault is connected (GitHub), commit it there with the message `<id> <code>: <title>` (`<id>`: the course entry's id, `greece` or `rome` for history); otherwise send the file and say where it goes.

## 3. Personal Mythology: the kit (`kit/` in the repo)
1. The report itself is its vault file (§2; since P71-3, 1 Nov 2026, there is no copy in the kit: `build.py` reads the vault through `vault.py`). Save the bibliography as `bibliography/<course>/r-<id>.md`; the writer's unsure list as `reviews/<session folder>/<course>-<id>-writer.md`.
2. `python3 check.py ../courses/<course>/<id>-<slug>.md` until OK.
3. Fresh check: a new agent or chat that has not seen the unit written, briefed with `reviews/units-9-13/BRIEF.md`; it writes findings and never edits. Verify every finding before applying it, as exact replacements; log a paragraph in the session's `log.md`.
4. `python3 register.py <course> "<model>" <id>`.
5. When the syllabus unit is complete: `python3 crosscheck.py <course> <ids>` and check every pointer between its modules.
6. Make sure the kit's `shell.css` is a copy of `design/theme.css`; if not, copy it.
7. Update `docs/courses-index.md` (§6) first, then `python3 build.py` and `python3 verify.py` (must print ALL CHECKS PASSED; it runs `index_check.py` on the index).
8. Look at the new page once at the three widths: `python3 verify.py --shots <dir> --page <panel id>` (the report's panel id, e.g. `rm11-3`), then open its six screenshots (phone, tablet, desktop; dark and light) with the Read tool and check by eye what the checks cannot: the hero and the first screen read as one page, nothing is cut at the column edge, tables and code scroll inside their box, the sidebar carries the right current item. The same run saves each figure of that panel on its own (`<width>-<panel>-fig-<nn>-<kind>-<theme>.png`, P41): open every one at phone width (390 px), dark and light, and check that its text sits inside its boxes, nothing overlaps, the caption is under it and, when it is wider than the column, it scrolls in its frame with the cue line; then open its frames sheet (`<width>-<panel>-fig-<nn>-<kind>-frames-<theme>.png`, P89: every frame a reader scrolls it across, stacked and numbered) at phone and desktop width, dark and light, and check the drawing is whole across the frames. A figure fault is fixed in the unit's declaration (shorter labels, another `per_row`, a box moved) or, if it is the drawing, in `kit/viz.py` or `design/theme.css`, never by styling the page. A fault is fixed in `design/theme.css` (then `cp design/theme.css kit/shell.css`), never in the page; rebuild and verify again.
9. Publish `academy/` to https://claude.ai/artifact/WwmQpUSqAUJvrcmLczppEH: read it with the Artifact tool first, then publish once with that `url`, `file_path` = `kit/academy/index.html` (the shell), `root` = `kit/academy` and `files` = the list `python3 publish_files.py` prints (the fetched files; one publish per printed line), never as a new artifact, never forced. Then `./deploy.sh`, which pushes the same build to GitHub Pages (https://apcanario.github.io/academy/). "Publish Academy" always means both: the artifact, then `deploy.sh`.
10. Add the session to `CHANGELOG.md` and update `README.md` "Where things stand".

## 4. Markdown course: the course data
The vault file saved in §2 is the unit Academy renders (A5): there is no other copy, and the unit counts as written because its file is in `<vault>` with front matter. The course data is its pack, `<data>` (AD5; S-DEC2: the `[pack]` table, read by `kit/pack.py`; `kit/build.py` renders it through `kit/mdcourse.py`). Filing a unit touches no `.py` file:
1. Add `intro` to the unit's front matter: one paragraph, on one line, saying what the unit is, when it was written, with or without search, and its known gaps from the unsure list; add `name` (the top bar's) only where it is not `<code> · <title>`. The unit's reading-page entry is derived from them (`id` `read-<code lower>`, its course, `title`, `covers` [code]); no `md` path: the build reads the vault file, and `WRITTEN` is derived from the vault. Without `intro` the unit still gets a page, with a one-line intro from its front matter; write it.
2. `STATUS`, `NEXT_UNIT` and `VERSION` are derived, never typed: the status "written <d Mon>" from the front matter's `written`, the next unit as the first row of `ORDER` with no file in `<vault>`, the version from the changelog's top row. A status the front matter cannot give ("rewritten <d Mon>") is a line under `[pack.status]` in `<data>`. Add the changelog row at the top: a `[[pack.changelog]]` table above the first in `<data>` (`date = '<yyyy-mm-dd hh:mm>'`, `text = '<version>. <code> <title> written (<model>) and filed; <what changed on the hub>.'`); its leading `v<n>. ` is the new version.
3. Do not edit `briefs.md`: briefs are never reworded. The unit's links join the course's Bibliography page automatically.

## 4b. The page's relief (both families; P96, 8 Nov 2026)
Every reading page either shows one object relief or records none (`method.md` §7, step 4b).
1. Read the writer's `Object:` line and the unit. The page gets a relief when its text discusses an object at length, not in passing (a section or several sentences about the thing itself); otherwise it gets none.
2. If the library (`design/outlines/outlines.json`) holds an outline of that object (or of its sign, said to be one: "an envelope (the sign for email)") serving the unit's course, add the page to `MAP` in `kit/p96_uses.py`: its panel id (`m<unit><module>` or `rm…` for history, `read-<code lower>` for a markdown unit), the outline's id and the words of the sentence that decides it, as they stand in the text. An outline already serving the course's page next door (two neighbouring reports of one unit) goes to this page only when its text allows no other, recorded in `NEIGHBOURS_OK` with the reason. An outline that served no page and was marked spare loses its `SPARE` line in `kit/p95_library.py`.
3. If the library lacks it, add it under P95's rules: from an open icon set on GitHub with an allowed licence (game-icons.net, CC BY 3.0, for ancient objects; Phosphor or Tabler, MIT, for everyday ones), a partial clone of the set at its commit (`git clone --depth 1 --filter=blob:none --no-checkout`), the file measured first (`python3 relief.py --probe <file>` with the set's background square taken out: no more than 40 regions, no thin part, a step of 3 px or more) and looked at as a silhouette; then its row in `L` in `kit/p95_library.py` (id, set, path, what it depicts with its article, the courses it serves, its keywords) with any homonyms in `EXCLUDE` (each takes out its whole sentence), `python3 p95_library.py <folder of the clones>` and `python3 relief.py <id>`. A candidate measured and not taken goes in `REJECTED` with its reason. If no open set holds a drawing of the thing the text discusses, the page gets none and the reason is said in the record.
4. `python3 p96_uses.py` until it prints its counts (it writes `design/outlines/uses.json` and the page's row in `design/outlines/uses-why.md`); with none, it lists the page under "None" with what its text names most. The page's relief is checked by `verify.py`'s relief checks (§5) and seen in the page's shots (§5.2: the relief under the scope line, its caption and credit, its lines inside the frame).

## 6. Index and count
- `courses-index.md`: the unit's row (status "written <date>", model, path to the vault file); for a search-on unit, a row in "Staleness checks due" (written + six months); the "N of M" line above the course's table. `python3 kit/index_check.py` until it prints "courses-index.md matches the sources" (§5 runs it again through `verify.py`).
- Markdown course: every unit gets a fresh check before filing (`audit-units` §3, "Fresh check of one markdown-course unit"; Brand + AI since 28 Oct 2026). A unit is not filed unless the fresh-check line ends its unsure list, `audits/<id>/fresh-check-<code>.md` exists as `audits/README.md` sets out, and that file's `verdict` matches the line (verdict and counts). The path goes on the unit's `courses-index.md` row.
- Commit and push `apcanario/learning` with the message `<id> <code>: filed`.
- Where the course keeps a register of its invented facts (`courses/ux/notes/perqo-facts.md`, S-1): append every fact the unit set, with its section, and list what the unit left free; a fact the unit changed is a fix to the earlier unit, made in the same chat.
- Refresh the changed Project mirrors with the Projects tool: `claude/BACKLOG-chats.md` and `claude/CHANGELOG-chats.md` every time, and `courses-index.md`, `method.md` and the course's three data mirrors (`claude/<course>-course.toml`, `-briefs.md`, `-syllabus-flags.md`) when this filing changed them. The Project holds only the named set of `method.md` §8 step 4: upload nothing outside it (no skill, no theme, no brief file). When the unit is the course's last, delete the course's three data mirrors from the Project and move the course's section of `docs/courses-index.md` to `docs/courses-index-archive.md` (`index_check.py` reads both). **Never upload a unit**: units are not mirrored into the Project (Pedro, 15 Nov 2026; the 49 copies were deleted that day); the repo and Academy carry them.
- Reply with what was filed where, the page's relief (its outline, or none), the Academy version, and the counter. Nothing else.
