# Start a new course

A course is not started by writing units. It is started by a syllabus, a brief per unit and its pages in Academy, in that order. In the repo a course of either family is one folder, `courses/<id>/`, whose `course.toml` is its entry (A5; S-DEC1, 20 Nov 2026: `kit/courses.py` finds it, so no existing file under `kit/` is edited (a history course adds its folder `kit/<id>/`)); it appears on the Academy home after one build. The rules are `method.md`; the requirement sets are `TEMPLATE_BLOCKS` in `generator/data/brand-ai/hub.py` (the syllabus and AI-rule requirements; the website ones are met by `design/theme.css`); the look is `design/theme.css` and nothing else.

## 1. Decide where it lives
**Every new course is a markdown course (P71; `method.md` §2 and §7).** A unit holds only its text, its sources and its ` ```viz ` blocks, one Markdown file in the course's vault; everything visual (layout, section bands, accordions, the figures' drawing, the styling) is the build's, and the same files make the site and the EPUB (`python3 build.py --epub <edition>`). The history format below (fragments in `kit/<id>/`) is how Greece and Rome were built; a new course, a new culture included, does not start in it.
- **A new culture in Personal Mythology** (as the kit built Greece and Rome, which are Markdown in the vault since P71-3, 1 Nov 2026) (Egypt, Persia, Norse and the others in `catalog.toml` `next`): the folder `kit/<id>/` with `syllabus.html` in the structure of `roman-syllabus.html` (units, modules, one `<pre>` prompt each, an audit unit last) and `prompts.json` holding `{}`; `courses/<id>/course.toml`, a copy of `courses/rome/course.toml` changed for the course, with `family = "history"`, `syllabus = "<id>/syllabus.html"`, `prompts = "<id>/prompts.json"`, `vault = "courses/<id>"` and the home-page fields Rome's has (parts, eras, ticks, lede, rules, spine, tile, card_units); its row removed from `catalog.toml` `next` and its id added to `course_order` there; the syllabus under `artefacts` in `provenance.json`. The reports arrive in `courses/<id>/` as Markdown (`<id>-<slug>.md`, `kit/AGENT-SPEC.md`) as they are written; until the first, the course home's Start button opens the syllabus. Then step 5's build and step 6. Briefs are the syllabus prompts plus `AGENT-SPEC.md` (add a section for the new course's conventions) and `WRITER-BRIEF.md`.
- **A new course beside Brand + AI's A and B** (a course C in the same data file): add it to `generator/data/brand-ai/` (`COURSES` in `hub.py`, its units in `units_data.py`, its track in `courses/brand-ai/course.toml` `tracks`); it appears in Academy on the next build.
- **A new markdown course family:** a new data folder. Steps 2 to 6 below.
Say which in the first line.

## 2. The frame (his decision, recorded)
Draft the frame before the syllabus: the pick, up to three reasons, the override condition, and where the evidence pushes back. Ask him to confirm or change the pick. One question, then build.

## 3. The syllabus
- 8–10 core units plus 2 or 3 deep dives, written last: the comparables and the hard-number one always; a third only when the subject has a documented practice worth verifying against its primary sources (as DD-B3 in course B). More than three, or another shape, needs the subject's own logic; say so if it does.
- A course goal in one sentence and three measurable outcomes, each mapped to the units that deliver it.
- Per unit: code, title, one-line scope, the deliverable it ships (built in full inside the unit), and the unit brief (`method.md` §4, Brief template: "Unit <code>, <Title>. [Search before writing.] Cover: … Deliverable: …").
- A search flag per unit: on only where facts are current.
- An explicit writing order, with interleaving where two units build the same asset.

## 4. The shared preamble
Fill the template in `method.md` §4 once for the course. Reader: copied from `reader.md`, nothing added. Sourcing standard: Part 1 of `sourcing-standard.md` plus a new part for this course (its acceptable sources and labels), which you add to `sourcing-standard.md`. Tone: the Project's. End with "End with the unit's deliverable, built out in full, not described."

## 4b. The standing rules (`method.md` §9)
Every new course carries the two standing rules of `method.md` §9, without being told them by its syllabus: the **carry-forward rule** and the **source-credibility floor**. Write the floor into the preamble's sourcing standard (step 4) and into the course's part of `sourcing-standard.md`: opened before cited, with a source log; a short seed bibliography checked for existence against Crossref's or the publisher's record before the first unit; an evidence grade on every claim, from a key the first unit sets; the sources that never count; interested parties labelled; fewer sources read in full; unsourced said or left out; the fresh checker verifying every reference's record and every cited claim. Write the carry-forward rule, with the course's names, into the course's prompts document (`docs/<slug>-prompts.md`), so that `kit/next_prompt.py` prints it in every writing row's prompt, the last row's included. They are not applied retroactively: no existing course's briefs or filed units change.

## 5. The course in Academy
1. Copy `generator/data/_template/` to `generator/data/<slug>/`. That folder is the course; its units will be filed in `courses/<slug>/`, which Academy reads (A5), so create no `units/` folder and keep no `WRITTEN` map.
2. `units_data.py`: `PRE` (step 4) and the units (step 3). `hub.py`: replace every `⟨…⟩` (identity, courses with goal and outcomes, `ORDER`, frame, ledes, changelog v1). Prose blocks use theme classes only (`design/README.md` lists them); no `style` attribute except `--c`, `--cc`, `--hc`.
3. `courses/<slug>/course.toml`, a copy of `courses/building-with-ai/course.toml` changed for the course: `family = "markdown"`, `data = "generator/data/<slug>/hub.py"`, `vault = "courses/<slug>"`, a `tracks` entry per course key (`tracks.<KEY> = ["<track id>", "<short name>"]`) and its `tiles` line. No existing file under `kit/` is edited: `kit/courses.py` finds the file. Add the id to `course_order` in `catalog.toml` where it should stand (unnamed, it comes after the named courses, sorted by id). A new track, if none fits, is a `[[tracks]]` table in `catalog.toml` plus, for now, its place in `_HERO_AT` in `kit/build.py`. Its pages get ids `<id>-<key>` (`#<id>-a`, `#<id>-a-briefs`); do not set `prefix` or `legacy_ids`, which keep Brand + AI's A3 anchors.
4. If a page needs a component the theme lacks, add it to `design/theme.css` section 5 with a one-line comment and copy it to `kit/shell.css`.
5. Step 6's `courses-index.md` section first (`verify.py` runs `index_check.py`, which fails without it), then `cd kit && python3 build.py && python3 verify.py` (ALL CHECKS PASSED). The home's expected tracks come from the course files through `courses.py`; nothing in `verify.py` is edited for a new course (step 5b's outline lists aside).
5b. **The course's outlines (P96, 8 Nov 2026; Pedro, 5 Nov 2026: "let's shoot for 10 per course at least").** A new course starts with at least ten outlines in the library (`design/outlines/`) of objects its texts will discuss, read from its syllabus and briefs: add the course to `TEXTS` in `kit/p95_library.py` (its vault folder), to `REL_COURSES` in `kit/verify.py`, to `NAMES` in `kit/p96_uses.py` and to `TONE`/`NAME` in `kit/p95_sheet.py`; add each outline as `file-unit` §4b step 3 sets out (an outline already in the library serves the course too when its texts will name it); until a unit names it, mark it in `SPARE` with the unit expected to discuss it. `python3 p95_sheet.py <dir>` and look at the course's cards: each reads as its object. As units are filed each page gets its relief or none (`file-unit` §4b), and the course reaches ten outlines in use by its tenth page.
6. Look at the new course once at the three widths: `python3 verify.py --shots <dir> --page <course panel id> --page <its build page id>`, then open the screenshots (phone, tablet, desktop; dark and light) with the Read tool and check by eye what the checks cannot: the course home reads as one page from the hero, the unit cards and build-order table sit inside the column, the drawer shows the course under its track. A fault goes to `design/theme.css` (then `cp design/theme.css kit/shell.css`), never the page; rebuild and verify again.
7. Publish Academy: the artifact (read first, publish once with its `url`: the shell `kit/academy/index.html` with `root` `kit/academy` and the fetched files `python3 publish_files.py` prints as `files`), then `./deploy.sh`.

## 6. Register it in the Project
- `courses-index.md`: a section for the course with every unit in build order (status "not written", model, search flag, vault path `courses/<slug>/<code>-<slug>.md`, and for history `(+ kit/<id>/r-<id>.html)`), rows numbered from 1, and the count line above the table (markdown: "0 of N written"; history: "0 of N content reports; M modules with the audit unit" under a `### <Short> (course N)` heading). `python3 kit/index_check.py` until it passes.
- `project-instructions.md`: add the course to the Purpose line only if it stays under 400 words.
- Reply with the course's Academy anchor, the unit count, the first unit to write and its model. Do not write a unit in this chat.
