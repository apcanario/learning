# P71-3 · Greece and Rome to Markdown

Backlog row P71-3 (the spec P71 (3), stage 1 of `docs/BACKLOG.md`), 1 November 2026, Opus 5.5, on the branch `p71-3` from `main` at `d71ea81`. The design comes first, as the row asks; the record of what was done follows it.

## The design

A history report is one Markdown file in the vault, `courses/<course>/<id>-<slug>.md`, read by `kit/mdcourse.py` (`history_html`) through `kit/vault.py`. The file holds the report's text, its trees and its figure declarations; everything visual is the build's. `mdcourse.history_html` turns the file into exactly the fragment the kit's `r-<id>.html` held, and `build.py` and `epub.py` lay that fragment out as before, so every page renders the same.

### Each element of a history fragment, and its Markdown

| In the fragment | In the Markdown | Rendered by `history_html` as |
|---|---|---|
| `<h2>`, `<h3>` | `## `, `### ` | the same |
| `<p>` with `<em>`, `<strong>` | a paragraph with `*…*`, `**…**` (`_…_` for emphasis inside bold) | the same |
| `<sup>`, `<sub>` (10 uses in 157 reports) | kept inline as written: Markdown has no form for them | the same |
| `<ul>`, `<ol>` | `- ` and `1. ` lists, tight | the same; a history list is always tight (an item's paragraphs joined back into it) |
| a list item holding a quotation or a tree (Greek 5.1, the capstones' gap prompts) | the item, then the quotation (`> `) or the tree (```` ```tree ````) indented under it | the same item, the block inside it |
| `<div class="tbl"><table>` | a pipe table (`\|` in a cell escaped) | the same, each row on one line as before |
| `<aside class="dispute"><strong>Where sources disagree.</strong> …</aside>` | a paragraph opening `**Where sources disagree.**` | the dispute box. The house's fixed opening is the marker: no other paragraph starts with it, and `check.py` already requires it of every box |
| `<blockquote>` | `> ` quotation | `<blockquote>` with its text unwrapped; consecutive quoted paragraphs, which Markdown joins, are one `<blockquote>` each, as written |
| Self-test: `<ol class="quiz">`, each `<li>` the question then `<details><summary>Answer</summary><p>…</p></details>` | a numbered item: the question, then the answer as indented paragraphs, the first opening `Answer:` (the capstones: `Model answer:`) | the quiz list, the answer in its closed box under that label |
| Carry forward: `<ol class="carry">` | the numbered list under `## Carry forward` | `<ol class="carry">` |
| `<pre class="tree">` | a ```` ```tree ```` fence, its drawing kept character for character (a leading blank line too) | `<pre class="tree">` |
| Greek and Latin display words | `*…*`: the fragments mark them only with `<em>`; no other markup exists to carry over | the same |
| the figure declaration, `<figure class="viz" data-viz><script type="application/json">…</script><figcaption>…</figcaption></figure>` | a ```` ```viz ```` block: the same JSON, `kind` first, the caption moved in as `"caption"`, kept exactly as the fragment had it (inline HTML and entities, as Brand + AI's captions carry links) | the drawing, by `viz.py` |

The file opens with front matter (`method.md` §7), then `# <title>` for a reader of the bare file; `history_html` drops both, since the page takes its h1 from the prompts index.

### What is generated, not written

The reading layout (P68: the scope line, the sticky section bar, one section at a time, "Whole unit"), the numbered section bands drawn from each `##`, the Self-test's answer boxes and the dispute box's frame, the accordions after the text (Sources from `kit/bibliography/<course>/r-<id>.md`, "How this unit was made"), the prompt panel (from the syllabus, through the prompts index), the provenance line and the flags (from `kit/provenance.json`), the eyebrow with the word count, and the EPUB's chapters. None of it is in a vault file.

### The kit's fragments: retired

`kit/greece/r-*.html` and `kit/rome/r-*.html` are deleted, not kept as generated copies: a second copy would be one more thing to drift, and the built site already holds each page (`kit/academy/<course>/r-<id>.html`). They stay in git history (`git show d71ea81:kit/greece/r-6.3.html`). Every reader now goes through `kit/vault.py`: `build.py`, `epub.py`, `check.py` (which takes the `.md` file, refuses any HTML in it but `<sup>` and `<sub>`, and checks the render), `register.py`, `crosscheck.py`, `biblio.py` (its extraction unchanged to the byte: the machine bibliographies are identical) and `verify.py`; `index_check.py` wants the vault path in `docs/courses-index.md`. `kit/courses.py` names each history course's `vault` in place of `frags`.

### Front matter

`code`, `title`, `course` (`greece · Personal Mythology · Greece`, `rome · Personal Mythology · Rome`), `model` (the writer in `kit/provenance.json`, the part before any ", reviewed with Fable 5.1"; the review status stays in `provenance.json`, which the flags are read from), `written`, `search: off`.

`written` comes from the record, `kit/CHANGELOG.md`'s sessions, only where a session fixes one day: Greek unit 12, 25 Oct; Rome units 0 to 4, 24 Oct; Rome unit 7, 25 Oct; Rome 8.1 to 10.5, 11.1, 11.2, 13.1 and 13.2, 25 Oct; Rome 11.3 to 13.8, 1 Nov (as filed). **Left out, 80 reports:** Greek 0.1 to 11.8 (70; session 1 ran 22 to 24 October), Rome 5.1 to 6.4 (10; session 4 ran 24 to 25 October).
