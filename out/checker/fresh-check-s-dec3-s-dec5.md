## Should-fix

**S1 · deploy.sh can push one edition into another edition's repo.**
File: `kit/deploy.sh:57`, and the fetch/reset block after it. `ACADEMY_DIR` (and `DEPLOY_DIR`) override the clone folder for every edition, and the script never checks that the clone's `origin` is the edition's `deploy_remote`. Evidence: `ACADEMY_DIR=/tmp/x bash kit/deploy.sh marketing-ai --dry-run` → `into: /tmp/x`. Without `--dry-run`, with `ACADEMY_DIR` pointing at the Academy clone (as the saved prompts `docs/sport-psychology-prompts.md:113` and `docs/supply-chain-execution-prompts.md:160` tell a chat to set), it would reset that clone to `apcanario/academy`'s main, replace its tree with the marketing-ai build and push it to the live Academy site. The same happens if two editions' remotes share a basename.
Fix: after `cd`-free setup and before the `if [ -d "$DEPLOY_DIR/.git" ]` block insert:
```
if [ -d "$DEPLOY_DIR/.git" ]; then
  HAVE="$(git -C "$DEPLOY_DIR" remote get-url origin 2>/dev/null || true)"
  [ "${HAVE%.git}" = "${REMOTE%.git}" ] || { echo "$DEPLOY_DIR is a clone of ${HAVE:-nothing}, not $REMOTE: set DEPLOY_DIR" >&2; exit 1; }
fi
```
and print the same check in the `--dry-run` branch (line "into:" followed by "(clone of <origin>)" or "(new clone)").
