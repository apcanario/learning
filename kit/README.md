# Academy (the Personal Mythology kit): start here

Academy is the one site for every self-study course in the Learning Project (`docs/academy.md`, decided 28 October 2026): the Personal Mythology courses (the history and mythology of one culture at a time) and Brand + AI. This folder builds it: `python3 build.py` writes `academy/`, the site published as the Academy artifact: `academy/index.html` is the shell; every report, each syllabus, the Brand + AI briefs and bibliography pages and each history course home are their own files beside it, fetched when opened (A2, P20 and P22, below). Each history course is a syllabus of modules, and each module is a long report (about 2,500–3,000 words) with named sources, dispute boxes, a ten-question self-test and three ideas to carry forward. Brand + AI is two Academy courses (A under Marketing, B under Technology) built by `mdcourse.py` from `generator/data/brand-ai/hub.py` and the units' Markdown. This folder is `kit/` in the private repo `apcanario/learning`, which is the home of everything (kit, design, generator, vault): a session clones the repo, works in `kit/`, and ends with a commit. The zip is retired as transport (28 October 2026).

## How a report is made

1. Its prompt is the module's `<pre>` in the course syllabus; the prompt is the contract.
2. A writer (one per module, in parallel) gets `WRITER-BRIEF.md`, the module id, output path, target and extra files to read, and writes the report in Markdown to the vault per `AGENT-SPEC.md` (since P71-3).
3. `python3 check.py ../courses/<course>/<id>-<slug>.md` until it prints OK; then the whole report is read and its checkable claims (dates, names, citations, who argued what) are verified.
   Then `python3 crosscheck.py <course> <ids>` for pointers and overlaps with the rest of the course.
4. `python3 register.py <course> "<model that wrote it>" <id>`.
5. `python3 build.py`, `python3 verify.py`, publish to the same artifact (title Academy), then `./deploy.sh` for GitHub Pages.

## Site layout and sizes

Decided at A2 (`docs/academy.md`, AD3): the site is a shell page plus one file per report, because a published artifact page is capped at 16 MB and the single page had reached 5 MB with two history courses. The shell holds everything but the reports; a report panel in it is an empty stub carrying `data-src`, the report file's path relative to the shell, and `shell.js` fetches that file the first time the report is opened, keeps it in the panel for the rest of the visit, and fetches the next report in the course in the background. Section links (`#m23-2`) into a report not yet opened load it first. If a fetch fails the panel says so and offers to try again. The artifact publishes `academy/index.html` as the page and every report through the Artifact tool's `files`, keyed by the same relative path: `python3 publish_files.py` prints the list (one call carries up to 255 files; it prints one list per call). `deploy.sh` copies the whole tree to Pages. Since P20 (28 October 2026) the two syllabi and the Brand + AI briefs and bibliography pages are fetched the same way (`academy/<course>/syllabus.html`, `briefs.html`, `bibliography.html`); a stub that is not a report lists the ids inside its file in `data-anchors`, so a link into it (`#rs-u3`, `#b-a2`) loads it first. The shell fell from 747 KB to 366 KB. Since P22 (28 October 2026) the history course homes are fetched too (`academy/<course>/home.html`; anchors `#greece-u3`); `shell.js` refreshes the continue button and opens the unit card once the home has landed. Shell 293 KB; a new history course now adds about 1 KB to the shell (its stubs and drawer) rather than 40 KB. The Brand + AI course homes stay in the shell (about 10 KB each).

## Design rules (don't drift)

`shell.css` is a copy of `design/theme.css` in the repo; change the theme there, then copy (`cp ../design/theme.css shell.css`), rebuild and republish. No page gets its own CSS.

Dark-first, with a working light mode and the sun/moon toggle; light is e-ink paper since P90 (4 Nov 2026): page `#e8e4dc`, cards `#f0ede6`, ink `#1b1915`, no pure white, the accents at full saturation within 4.5:1 (`contrast.py`; `design/README.md` has every token). Page `#0a0a0c`, cards `#131316`, borders `#1e1e24`. DM Sans for text, Space Mono for labels, Gentium Book Plus for Greek or Latin display words. Accents `#ff6b6b` (Greece), `#9b5de5` (Rome), plus `#f4a261`, `#2a9d8f`, `#457b9d`, `#e9c46a`; no grey as a dominant accent. Mobile-first, max width 700 px, every page carries its own `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` (without it phones lay the page out 980 px wide and shrink the text to 40 percent), 44 px touch targets, fixed frosted top bar, full-height slide-out drawer, at least 6 px between stacked cards.

- **Requirements:** Python 3; Node for the optional script-parse check; Playwright with Chromium for `verify.py`. `verify.py` serves the theme fonts from `fonts/` (P39: DM Sans, Space Mono and Gentium Book Plus woff2 from the @fontsource packages, SIL OFL, `fonts/OFL.txt`) in place of Google Fonts, so every check measures the fonts a reader gets; it fails if they do not load.
