# Academy (the Personal Mythology kit): start here

Academy is the one site for every self-study course in the Learning Project (`docs/academy.md`, decided 28 October 2026): the Personal Mythology courses (the history and mythology of one culture at a time) and Brand + AI. This folder builds it: `python3 build.py` writes `personal-mythology.html`, the page published as the Academy artifact. Each history course is a syllabus of modules, and each module is a long report (about 2,500–3,000 words) with named sources, dispute boxes, a ten-question self-test and three ideas to carry forward. Brand + AI is, until A3 lands, a placeholder course panel on the Academy home whose content is read from `generator/data/brand-ai/hub.py` and whose units are read on the Brand + AI hub. This folder is `kit/` in the private repo `apcanario/learning`, which is the home of everything (kit, design, generator, vault): a session clones the repo, works in `kit/`, and ends with a commit. The zip is retired as transport (28 October 2026).

## How a report is made

1. Its prompt is the module's `<pre>` in the course syllabus; the prompt is the contract.
2. A writer (one per module, in parallel) gets `WRITER-BRIEF.md`, the module id, output path, target and extra files to read, and writes an HTML fragment per `AGENT-SPEC.md`.
3. `python3 check.py <course>/r-<id>.html` until it prints OK; then the whole report is read and its checkable claims (dates, names, citations, who argued what) are verified.
   Then `python3 crosscheck.py <course> <ids>` for pointers and overlaps with the rest of the course.
4. `python3 register.py <course> "<model that wrote it>" <id>`.
5. `python3 build.py`, `python3 verify.py`, publish to the same artifact (title Academy), then `./deploy.sh` for GitHub Pages.

## Technical notes

- **Panel ids:** `#home` (root, the Academy home) and `#changelog` (root, rendered from `CHANGELOG.md`; the prev and next arrows stay hidden on root pages). `#brand-ai` is the Brand + AI placeholder (`data-kind="course"`, its own drawer context, no report panels until A3). Greece: `#greece`, `#syllabus`, reports `#m01` … `#m118` (2.3 → `m23`). Rome: `#rome`, `#rome-syllabus`, reports `#rm01` … (1.2 → `rm12`). Panels carry `data-ctx` (course), `data-kind` (`root`, `course`, `syllabus`, `report`) and top-bar data; report titles come from the drawer.
- **Browser storage:** `hellas-reports-tab` is the last report read in any course, `pm-last-<course>` the last per course, `hellas-units-open` the open drawer units (Rome keyed `rome:<n>`), `hellas-theme` the theme.
- **Adding a course:** a history course: write its syllabus in the same structure, add a dict with `family='history'` to `COURSES` in `courses.py` (remove it from `NEXT`), create its fragments folder, an empty prompts index and an empty entry in `provenance.json` (with the syllabus under `artefacts`), then build and verify. A markdown course (A3 onwards): a dict with `family='markdown'` and a `data` file in the shape of `generator/data/brand-ai/hub.py`.
- **Unchecked and next:** a report registered with `"(unchecked)"` in its `provenance.json` entry (`python3 register.py rome "Opus 5.5 (unchecked)" 10.5`) shows an orange "unchecked" pill in the drawer, on the course home, in the syllabus and on the report; re-register it with `"Opus 5.5"` once checked. A module listed in a course's `next_up` (in `courses.py`) shows a blue "next" pill until it is written, and a unit whose unwritten modules are queued reads "next session".
- **Requirements:** Python 3; Node for the optional script-parse check; Playwright with Chromium for `verify.py`.
